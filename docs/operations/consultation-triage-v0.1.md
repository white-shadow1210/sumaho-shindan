# Consultation Triage v0.1

- **Version**: 0.1
- **Created**: 2026-09-23
- **Origin**: FT-001 / CF-001
- **Purpose**: 街のスマホ相談士における初動判断を標準化する

## 1. 基本思想

> 何でも直す人ではなく、まず相談できる人。  
> 自分で解決できることは一緒に。  
> 専門対応が必要なら、適切な場所へつなぐ。

相談者が最初に困るのは、「直し方」だけでなく、

> **どこに相談すればいいのか分からない**

ということも多い。

その入口を担う。

## 2. 標準フロー

```text
相談受付
  ↓
状況確認
  ↓
緊急性・データ消失リスク確認
  ↓
安全に試せる基本操作
  ↓
その場 / 遠隔で解決可能か判断
  ├─ Yes → 一緒に解決 → 結果確認 → 記録
  └─ No
       ↓
     適切な専門窓口を判断
       ↓
     接続 / 案内
       ↓
     可能なら結果確認
       ↓
     Case Noteへ学びを反映
```

## 3. Step 1｜状況確認

最低限、以下を確認する。

- 何が起きているか
- いつからか
- 直前に何をしたか
- 画面に何が表示されているか
- 電源は入るか
- 通信できるか
- バックアップはあるか
- Apple / Google等のアカウント情報を本人が把握しているか
- PCや別端末など、必要な環境があるか
- 本人が操作を続けても安全そうか

## 4. Step 2｜リスク判定

以下に該当する場合は慎重に扱う。

### High Risk
- 初期化・復元を伴う可能性
- データ消失の可能性
- バックアップ有無が不明
- 画面ロック・アカウント復旧
- 決済・金融・本人確認
- 不正アクセス疑い
- 水没・発熱・膨張・破損
- OS更新失敗・復旧画面
- PC操作が必要だが本人が不慣れ
- 遠隔では状態確認が不十分

High Riskでは、無理に「直す」ことを優先しない。

## 5. Step 3｜安全に試せる基本操作

データを消さない操作を優先する。

例:

- 画面表示・通信状態の確認
- 通常再起動
- 必要に応じて強制再起動
- Wi-Fi / モバイル通信確認
- アプリ再起動
- ストレージ確認
- 通知設定確認
- 公式アプリ / 公式サイトからの状態確認

### 禁止寄りの判断

バックアップ状況が不明なまま、

- 初期化
- 復元
- OS再インストール
- アカウント削除
- 大規模なデータ削除

を安易に案内しない。

## 6. Step 4｜自分で対応するか、つなぐか

### 自分で対応しやすい
- 基本設定
- 通知
- 文字サイズ
- Wi-Fi
- アプリ操作
- アカウント概念の説明
- 迷惑SMSの見分け方
- 容量整理の考え方
- 買い替え判断の整理

### 専門窓口へ接続しやすい
- 物理故障
- データ復旧
- OS復旧
- メーカー診断
- 正規修理
- SIM再発行
- 契約名義・本人確認を伴う手続き
- 金融・決済不正
- 法的・警察相談が必要なケース

## 7. 接続先の考え方

「とりあえず携帯ショップ」ではなく、問題の種類から接続先を選ぶ。

| 問題 | 主な接続先 |
|---|---|
| iPhoneハード/OS復旧 | Apple / Apple正規サービス |
| Android端末故障 | メーカー / 正規修理 |
| SIM・契約 | 契約キャリア / MVNO |
| データ復旧 | 専門事業者 |
| 決済・カード不正 | カード会社 / 金融機関 |
| 詐欺・犯罪疑い | 警察 / 消費生活相談等 |
| 軽微な設定 | 街のスマホ相談士で対応可能 |

## 8. 相談終了時

可能なら以下を確認する。

- 解決したか
- 次に何をするか本人が理解しているか
- 誰に相談するか分かっているか
- 再発防止策があるか
- 再相談が必要か

## 9. 記録

個別ケースから学びがあった場合は、匿名化して `docs/case-notes/` に残す。

記録するもの:

- 症状
- 直前操作
- 判断
- 実施した対応
- 専門窓口への接続有無
- 結果
- 良かった点
- 改善点

記録しないもの:

- 氏名
- 電話番号
- 住所
- 生年月日
- アカウントID
- パスワード
- 認証コード
- 個人を特定できるスクリーンショット

## 10. v0.1の位置づけ

このフローは完成版ではない。

今後の相談会・個別相談で、

- 判断漏れ
- 不要な移動
- 遠隔対応の限界
- 専門窓口接続の精度
- 相談者の理解度

を見ながら更新する。

### Update trigger
同種のケースが2件以上発生した場合、または重大な判断ミスにつながり得る事例が発生した場合は、v0.xを更新する。
